# Omnific 代码规范

1. 编辑前读取当前仓库以及对应目录中的 `AGENTS.md`。
2. 新建或重写面向 Codex 的 `AGENTS.md` 时使用中文，新建或重写面向用户的 `README.md` 时使用英文；技术标识保留准确的原文。仓库另有语言要求时遵循仓库规则。
3. 使用第三方包或 workspace 包时，优先遵循当前安装版本的官方推荐写法和项目内最新用法；不要继续沿用旧版本 API、过时配置或已弃用模式。
4. 新增第三方依赖时锁定明确版本，不要使用 `latest`、`*`、宽泛 range 或隐式 tag；同时提交对应 lockfile 变更。
5. 函数和组件先接收完整参数，再在函数体中解构。参数结构复杂、需要复用或抽取后更清晰时，定义具名 `type` 或 `interface`。
6. 优先复用 `@omnific/utils` 已有的类型谓词和工具方法，不要重复实现运行时判断。
7. 使用 `isNil`、`hasValue` 或更具体的谓词进行空值判断。
8. 普通业务分支优先使用语义与分支意图一致的正向条件。除非仓库完全禁止，否则仅在立即退出当前路径的守卫分支中使用逻辑非。
9. 不要通过与 `true` 或 `false` 比较来规避逻辑非。
10. 为导出的函数、方法、组件、Hook、类型和接口添加 JSDoc 或 TSDoc。为公开类型中具有业务含义的属性分别添加文档，不要用类型声明顶部的笼统注释代替属性说明。
11. 重命名时同步修改声明、导出、路径和所有调用方。删除旧入口，不要仅为兼容添加别名、wrapper、barrel 或 deprecated re-export。
12. 从 `AGENTS.md`、package scripts 和项目配置中确定验证命令；代码修改后至少运行仓库定义的 typecheck 与 lint，不要臆造不存在的脚本。
13. 当前 `AGENTS.md` 中更严格或更具体的规则具有更高优先级。
